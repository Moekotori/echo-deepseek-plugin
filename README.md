# ECHO DeepSeek 插件

为 ECHO 提供有来源的音乐资料、音乐对话和歌单预览。插件运行在 ECHO 的沙箱中，使用用户自己的 DeepSeek API Key。

[Steam 创意工坊](https://steamcommunity.com/sharedfiles/filedetails/?id=3823840647) · [ECHO Workshop SDK](https://github.com/Moekotori/echo-workshop-sdk) · [DeepSeek API 文档](https://api-docs.deepseek.com/)

## 功能

- 为艺人和专辑信息页生成中文资料、创作人员、发行版本及引用来源。
- 搜索相关 B 站、YouTube MV 和现场视频，以外部链接展示。
- 查询歌曲背景、原唱翻唱、创作人员参与作品、新作与演出。
- 连续对话并生成可编辑的歌单预览；用户点击创建后才写入本地歌单。
- 默认在本机匹配推荐歌曲；可选择按自然语言组合曲风、BPM、年份、单曲时长和纯音乐条件查询曲库。
- 从当前歌曲沿已查证的作曲、编曲、制作署名探索其他作品，匹配本机曲库，并附现场、访谈和制作视频来源。
- 保存前验证 Key 和账户余额，复用已保存配置。

## 使用

需要 ECHO 26.10.21 或更新、并包含插件安全存储及资料提供方接口的主程序构建。仅有相同版本号不代表接口一定齐全。此仓库只包含插件，主程序的加密配置隔离等修复需由 ECHO 提供。

1. 从创意工坊订阅，或自行构建并导入 `.echo-workshop.zip`。
2. 在 ECHO 中启用插件，从侧栏进入 DeepSeek。
3. 展开 API Key 设置，填入自己的 Key 并保存。插件包中没有预置 Key。

开启“让 DeepSeek 从曲库选曲”后，可在对话里输入：“找 BPM 120–160 的电子纯音乐，单曲不超过 5 分钟，准备半小时歌单”。组合条件由宿主数据库筛选，每次返回最多 8 首预览，曲库查询每轮最多 3 次；模型不能声称已扫描整个曲库。歌单按真实秒数控制不超出目标，缺少有效时长的歌曲不加入限时草案，不保证凑满；预览显示实际时长，点击创建才保存。情绪、语言和相似风格属于推荐判断，不能当作已完成音频分析。

点击“使用当前歌曲”→“探索相关作品”，也可以直接输入“曲名 — 艺术家”。探索优先沿最多两位已查证作曲、编曲或制作人员查其他作品，显示关系及本机匹配，可准备歌单并继续探索下一首。没有署名证据时不猜测关系；作曲人不等于演唱者。全部缓存命中时不重复搜索和生成，但每次会重新匹配当前曲库。

源码版本以 [manifest.json](manifest.json) 为准。创意工坊条目的实际版本以其发布记录为准。

## 缓存与费用

命中本地结果缓存时，不调用网页搜索或模型生成。缓存通过插件存储保留，重开页面和重启应用后可复用；清理应用数据会影响缓存保留。

| 内容 | 有效期 |
| --- | ---: |
| 专辑、歌曲背景、作品关系、创作人员资料、探索视频 | 30 天 |
| 艺人资料 | 7 天 |
| 新作与演出 | 6 小时 |

详情手动刷新会重新查询。名称的大小写和多余空白归一化，发行版本标记和年份仍区分；同一客户端内重复请求合并。详情、研究及探索视频三类缓存各最多 96 条且 JSON 总长度最多 384,000 字符；各自内存最多 24 条且 JSON 总长度最多 96,000 字符。

研究结果命中后仍重新匹配当前曲库，不缓存本机歌曲对象。对话固定系统提示前缀，历史最多 10 轮，超出时一次移除 5 轮；只在内存中保留对话。DeepSeek 服务端缓存命中以实际返回的 `usage` 为准，不能保证固定命中率或账单降幅。

## 数据与权限

插件的 API 请求只发往 `api.deepseek.com`。资料检索发送艺人、专辑等查询信息；对话发送用户输入和有界历史。只有开启曲库选曲时，才发送当前查询得到的曲名、艺人、专辑、曲风、年份、时长及临时引用，不发送本机路径、歌曲 ID 或音频。

Key 由 ECHO 主进程使用系统安全存储保存，不写入源码、日志或资料缓存。关闭曲库选曲会清空当前对话。插件不改写原始媒体、封面、歌词或标签，不自动写入歌单；模型只能提出预览。外部视频以链接打开，不解析、下载或内嵌播放。

## 开发

需要 Node.js **22.13+（22.x）或 24+** 和 npm。项目 `.npmrc` 固定可选 peer 依赖的解析方式，避免 npm 10 的 Vitest 可选依赖循环；所需的 Vite 与 jsdom 已直接声明。首次克隆后：

```sh
npm ci
npm test
npm run build
npm run check:package
```

构建产物：

- `content/`：可导入/发布的工坊内容，含完整性清单和许可证。
- `dist/echo-deepseek-plugin-<version>.echo-workshop.zip`：本地导入包。

构建和测试不需要 API Key，也不会请求 DeepSeek 或上传 Steam。`echo.workshop.project.json` 保留原公开工坊条目的项目资料；本仓库不包含发布凭据或自动发布脚本。新分支的插件如需单独发布，应使用自己的插件及工坊条目标识。

源码在 `src/`；`*.test.mjs` 使用 Node.js 测试运行器，`key-panel.test.ts` 使用 Vitest 与 jsdom。构建脚本独立运行，不依赖 ECHOSteam 主程序仓库。`vendor/` 仅包含 MIT 许可的预览生成工具及原许可证。

## 从 ECHOSteam 同步

日常开发以 ECHOSteam 的 `workshop/deepseek-details/` 为源码主目录。这个仓库负责独立构建和公开发布；外部 PR 对插件源码的修改先合回主目录，再导出，避免两边分别维护。

两个仓库放在同级目录时，在本仓库执行：

```sh
npm run sync:check
npm run sync
```

`sync:check` 只列差异，有差异时退出码为 1；`sync` 更新本地文件，保留可审阅的 Git diff。默认源码位置为同级的 `ECHOSteam/workshop/deepseek-details`，其他目录可显式指定：

```sh
npm run sync -- --source /path/to/ECHOSteam/workshop/deepseek-details
```

需要一条命令验证并同步到 GitHub 时，在独立仓库干净且位于 `main` 的情况下执行：

```sh
npm run sync -- --push
```

该命令先检查目标远端和 Git 状态，获取远端 `main` 并仅允许快进，再同步、测试、构建和校验导入包；通过后只提交本次同步文件并推送，最后回读远端 SHA。无差异时不重复验证或生成提交。任何冲突、验证失败或预算超时都会停止；不会自动覆盖本地改动、重置分支或强推。默认不联网，只有 `--push` 才访问 GitHub。

同步范围是 `src/`、插件测试、素材说明、工坊项目资料、`manifest.json` 和 `package-files.json`。版本来自 `manifest.json`，会同时更新独立仓库的 `package.json` 和锁文件版本。两份构建脚本都读取相同插件清单和静态资源清单。

独立仓库的 README、许可证、npm 依赖、构建适配器和同步工具保留；主程序代码、开发记录、`.env`、凭据和构建产物不导出。`.sync-state.json` 只记录上次导出内容的哈希，不含机器路径；它用于识别独立仓库上的文件改动，并只删除之前确实导出过、现在已从源码移除的文件。
